# Limitations and unresolved work

- The fixed test set contains six experiments (two per link); estimates have substantial uncertainty and are sensitive to individual runs.
- Current task is conditional localization: annotated phase labels and fault-phase start select the window. There is no validated phase-blind online detector/localizer.
- The fixed-split result uses the original ID membership on a revised dataset with new physical evidence; it is not an exact re-run on the historical data.
- The topology ranker trails RF: 3/6 vs 4/6 Top-1 on the updated fixed split, and 10/18 vs 15/18 in the saved LOEO comparison. It has a class-specific failure on s2-s3.
- Top-3 is 100% by construction with three candidates.
- Onset/propagation components often do not discriminate: threshold crossings can be absent or align at the same sample. Annotated fault-phase timing can differ from the real causal onset.
- Historical switch-port-to-link mappings are setup-derived, not runtime verified. New runs 21 and 23-29 have captured runtime mappings; pilot physical 31 also recorded its runtime mapping but is excluded from v3.
- RX counters/rates/throughput are zero in the 17 historical source experiments but nonzero in all eight recollections. This acquisition-era shift is real in the stored data, but its cause is unknown and limits cross-cohort interpretation of RX-dependent results. Same-split ablation shows RF unchanged by removing RX (80%/88% Top-1/Top-2), while the topology ranker changes from 52%/88% with all features to 36%/64% TX-only; RX-only results are also weak. Treat these as exploratory sensitivity results, not a fix or confirmation.
- TX rate and throughput are nearly perfectly correlated in training-normal telemetry; feature redundancy must be assessed by context and measurement generation.
- Run 23's link-failure trial had roughly 77% UDP sequence loss. Valid process completion is not equivalent to a healthy traffic path.
- Run 21's original run metadata remains FAILED_INVALID; its inclusion in one candidate depends on separate preserved-evidence re-audit and revised iperf2 parser semantics. Do not treat the original metadata status as repaired.
- Run 22 is provisional because trustworthy process exit/final-summary/duration evidence is absent. Run 20 is invalid.
- GCN/GCN+LSTM phase-classification results are not evidence of root-cause localization. A grouped v3 LOEO evaluation path has been implemented to compare graph-only, temporal-only, and graph-temporal localization with same-fold RF/topology baselines; see `RESULTS_BALANCED_V3.md` for its evidence and limitations. All such rankings still use an oracle-selected fault window.
- Small single-topology controlled experiments do not establish broad SDN generalization or causal propagation.
- A single 6 Mbps UDP engineering pilot completed at logical 27 / physical 31 after the first attempt (logical 26 / physical 30) failed validation and was preserved as `FAILED_INVALID`. Its criteria were chosen after observing the failed attempt, and its whole-run iperf loss cannot separate baseline from outage loss. No post-run cleanup snapshot is persisted. This is not preregistered evidence, a repeatability study, or a model-evaluation example; neither pilot run is admitted to v3. The VM is reachable when the existing non-default SSH key is selected explicitly. Follow-up collection remains blocked because all runner-registered physical/logical pairs have been used and the prospective cohort's normal-only and phase-attributed receiver-evidence features are not implemented.
- The isolated live demo is a single run. Logical 40 / physical 44 is `FAILED_INVALID` and excluded. Logical 41 / physical 45, the final authorized attempt, is valid and was localized correctly (Top-1 `s2-s3`) by RF trained on the 17 historical experiments, using the oracle fault window. One correct prediction is not an accuracy or repeatability estimate. Its training experiments have zero RX counters while it has nonzero RX; the model's active metrics are TX-only. No further physical run is authorized.
- The proposed independent low-load cohort requires three normal-only controls and three fault/recovery repetitions per link, with phase-resolved receiver intervals and preflighted unique IDs. The current runner does not implement the normal-only mode; the prospective criteria and prerequisites are frozen in `TRAFFIC_PROFILE_REPEATABILITY_PROTOCOL.md`, but no cohort result exists.

## Highest-value next research step

Implement and validate the prospective low-load cohort runner path (including normal-only controls and per-interval delivery), then collect the planned cohort only after VM access and ID preflight are restored. Separately, improve online detection only with training-only choices and new held-out experiments; the current detector is unsuccessful. Do not tune against existing held-out experiments or claim causal RCA without intervention-backed causal ground truth.
